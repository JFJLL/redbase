# RedBase 套餐与积分 V2 数据迁移与上线切换方案

## 1. 迁移设计与权益保障准则

1. **历史永久余额原样保留**：
   切换前已有剩余余额统一归入“历史保留积分”批次 (`source_type = 'legacy'`)，保持原有不设到期日规则 (`expires_at = NULL`)。不得因旧商品曾命名“单月版”或“包年版”便追加到期日。
2. **来源明确与开账对齐**：
   历史账户余额以开账迁入批次为准，迁移前后每个账户可用额度与在途预占口径 100% 对齐。
3. **旧订单跨版本履约**：
   切换前创建、切换后支付的旧订单（如 `business-monthly`、`business-annual`），继续按原永久积分规则履约入账，并记录幂等唯一标识。
4. **迁移幂等可重跑**：
   批次迁移具有用户与批次级防重机制，重复执行迁移不会重复增发旧余额。

## 3. SQLite 生产备份与操作要求

SQLite 数据库启用 WAL 模式时，不可直接通过文件复制正在写入的 `.sqlite` 文件。必须使用标准备份流程：

```bash
# 1. 执行 WAL 检查点确保活动写入刷盘
sqlite3 /path/to/redbase.sqlite "PRAGMA wal_checkpoint(TRUNCATE);"

# 2. 使用 SQLite 官方安全在线备份命令
sqlite3 /path/to/redbase.sqlite ".backup /path/to/backups/redbase_pre_v2_backup.sqlite"

# 3. 校验备份文件完整性
sqlite3 /path/to/backups/redbase_pre_v2_backup.sqlite "PRAGMA integrity_check;"
```

## 4. 上线切换与回滚边界

### 4.1 切换前边界（尚未产生新交易）
- 若执行迁移或启动检测发现异常，且未开放公网流量与交易：
  停止服务进程，直接恢复切换前全量备份文件，排查原因。

### 4.2 交易后边界（已产生新交易）
- **严禁直接恢复上线前快照**：此举将抹除上线后用户已支付的真实订单、升级记录与扣减流水，造成账务严重错乱。
- **向前修复策略**：
  若遇到业务异常，应关闭新套餐购买入口 (`ALIPAY_ENABLED=false` / `WXPAY_ENABLED=false`)，但保持旧订单回调对账与年付正常发放。通过发布补丁或数据修复脚本向前修复，禁止回退覆盖账本。
